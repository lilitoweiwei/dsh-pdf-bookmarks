# dsh PDF 书签插件

在 DeepSeek Harness 右侧文件预览中增加 **PDF 书签** 查看器，提供文档目录与本地阅读书签。

## 使用

1. 在现有任务的工作区文件栏打开 PDF。
2. 如果仍是原查看器，在文件头部的查看器菜单选择 **PDF 书签**。
3. 工具栏的 **☰** 开关导航，**文档目录** 展示 PDF 自带章节，可展开层级并点击跳转。
4. 点击 **☆ 书签** 收藏当前阅读位置，可直接输入名称并保存。
5. **我的书签** 支持点击跳转、行内改名和删除。重开同一 PDF、切换任务或重启桌面版后仍可读取。
6. **自动续读**：离开时停在哪一页，下次打开同一 PDF 会自动回到那里。顶部提示条写明恢复到的页码，点 **回到开头** 可重置续读位置并跳到第一页（续读位置记作第 1 页，等价于清除）。

较窄的侧栏以覆盖面板显示导航，点击目标后自动收起。工具栏提供页码跳转、适应宽度和固定缩放；正文支持连续滚动和文字选取。

没有内置目录的 PDF 显示说明，仍可添加个人书签。需要密码的 PDF 沿用现有引擎的限制，暂不支持输入密码。

## 数据

个人书签只保存文档内容 SHA-256、名称、页码、页内相对位置和创建时间，存在应用自身 origin 的 localStorage 中，键前缀为 `dsh-pdf-bookmarks:v1:`。同一内容的 PDF 副本共用书签；内容变更后使用新的集合。自动续读位置单独存在 `dsh-pdf-bookmarks:progress:v1:<内容 SHA-256>`（页码、页内相对位置、更新时间），不写进书签集合；关闭、刷新、切换任务后都保留。不会修改 PDF，也不会把 PDF、书签或阅读进度放进模型请求、原有任务记录或账号配置。

已有书签数据损坏、版本不认识或本地存储不可写时，显示错误并保留原数据。卸载插件不清空书签；清除桌面应用的全部网站存储则会移除这些书签。

## 兼容性与故障回退

从 **0.1.2** 起采用能力兼容模式：不声明 `engines.dsh` 或 DSH 相关 peer 版本限制，也不维护宿主版本白名单。升级 dsh 后默认尝试加载，版本号变化本身不会停用插件。启用条件位于 `cordis.patch.yml`：加载入口前，`guard.cjs` 只核对两个构建文件的 SHA-256；文件缺失、损坏或检查异常均仅禁用本插件。客户端在注入前检查 `effect`、`slots.inject/register` 与 `documentPreviews.register`，接口缺失时保留内置查看器；部分注册失败时立即清理自身注册项。

Host 入口 `index.js` 无运行时依赖、不提供或替换任何核心服务。正式插件不安装 `dsh-tools`、Cordis 或其他 dsh 核心包。客户端接口注册异常会被捕获；PDF 引擎在打开 PDF 时才加载，加载失败会移除增强预览定义并交回内置查看器；正文错误边界提供 **使用内置 PDF 预览**。这是对已验证版本及测试故障场景的保护。默认尝试加载不等于承诺所有未来版本兼容；宿主彻底改变模块加载协议或接口语义时仍可能需要适配。

## 安装与停用

0.1.2 在 **macOS Apple Silicon、dsh Desktop 0.2.1-rc.5** 上验证独立 Host 加载与故障隔离；此前 rc.2/rc.3 的验收记录保留在历史更新说明中。其他版本默认尝试加载，但未逐一实测；Web、Windows、Linux 仍未经验证。

本 fork 当前版本为 **0.1.5**（上游最新为 0.1.2；本 fork 未发布 npm 包，本机以源码 submodule + `link:` 安装）。推荐从 [最新发布页](https://github.com/woody-dx/dsh-pdf-bookmarks/releases/latest) 下载预构建安装包，或直接下载始终指向最新正式版的 [dsh-pdf-bookmarks.tgz](https://github.com/woody-dx/dsh-pdf-bookmarks/releases/latest/download/dsh-pdf-bookmarks.tgz)。在桌面版 **插件 → 添加插件** 中填写下载文件的绝对路径，然后启用插件并完整退出、重新打开 dsh。安装包包含完整 `lib/` 和许可证，不需要构建或运行安装脚本。

从旧版升级时使用同一个插件名称安装新包，不必先卸载或清除应用存储。更新不会迁移、清空个人书签，也不会修改任务或账号。重启后可在插件详情页核对版本 `0.1.2`，再在 PDF 的查看器菜单选择 **PDF 书签**。已有 GitHub 标签、旧安装包和已经下载的文件不会自动变成新版，请下载最新资产后更新。

也可在桌面版 **插件 → 添加插件** 中输入 `dsh-pdf-bookmarks@latest`，从 npm 安装。使用 CLI 时应使用当前桌面版随附的 CLI，执行 `dsh plugin --profile desktop add dsh-pdf-bookmarks@latest --save-exact --ignore-scripts`，随后完整退出并重新打开应用。npm 的 `latest` 与 GitHub 最新正式 Release 保持一致。

也可下载仓库默认分支的源码 ZIP 并解压，在桌面版添加插件时填写解压目录的绝对路径。源码仓库同样包含预构建 `lib/`。不要使用旧版全局 `dsh` CLI 管理较新的桌面 profile。

插件遵循 `dsh.bundle` 组合包机制。启动保护从当前 profile 的包解析找到自身，不要求源码位于特定用户名或 `~/.dsh/plugins` 路径。在 **插件 → 已安装插件** 中可启停和卸载；列表未更新时点击 **刷新**。删除本地源码前应先停用并移除安装引用。

停用可在 dsh 插件列表中禁用本插件，或在 profile patch 最后增加：

```yaml
- id: pdf-bookmarks
  disabled: true
```

再次启用前删除这条手工禁用覆盖。停用或使用查看器菜单切回 **PDF** 后，内置查看器继续工作。删除本地源码目录前应先停用并移除 profile 引用。

## 开发与验证

源码、测试和构建脚本随本地目录保留。开发依赖仅用于构建测试，不安装到 dsh profile。

```sh
npm ci --ignore-scripts
npm test
npm run build
node scripts/host-smoke.cjs
```

`vendor/source.json` 记录来自当前应用的离线 PDF 引擎快照、版本和 SHA-256。构建仅调整模块身份、样式归属及自身所需的低层导出。第三方许可证见 `THIRD_PARTY_NOTICES.md` 和原始快照文件头部。修改源码后必须重新构建以更新完整性清单。

`test/harness.jsx` 和 `scripts/harness.mjs` 是隔离的浏览器验收入口，使用合成三页 PDF，不读取个人任务。`scripts/host-smoke.cjs` 使用独立数据目录验证普通安装、本地链接、未来版本号、引擎缺失、构建损坏和保护脚本异常等场景；需要本机安装上述 dsh Desktop，脚本不会读取真实 profile。

## 本仓库与原版的差异（fork）

本仓库 fork 自 [woody-dx/dsh-pdf-bookmarks](https://github.com/woody-dx/dsh-pdf-bookmarks)（MIT），在 `0.1.2` 基础上增加 **自动续读**（`0.1.3`）、**大文档渲染性能重写**（`0.1.4`）与 **非安全上下文可用性修复**（`0.1.5`）：

- 阅读位置按文档内容 SHA-256 自动保存（滚动停止 600ms、切走、关闭页面时落盘），重新打开自动回到上次位置；
- 续读使用独立的 `progress:v1` 键，旧版书签数据原样读取，不需要迁移；
- 续读提示条可一键 **回到开头** 或关闭，不会和手动书签、目录跳转互相覆盖；
- 原有引擎、书签格式、目录与缩放行为不变。

`0.1.4` 把页面列表改成虚拟化渲染（见下节），对外行为不变：目录、书签、续读、缩放、文字选取、页码跳转均保留，`progress:v1` 与 `v1` 存储格式不变。

## 为什么大 PDF 不再卡（0.1.4）

`0.1.3`（上游实现）会把每一页都挂成 DOM 节点，且滚动时逐帧量取全部页框：926 页的文档里有 926 个页框、926 个 IntersectionObserver，每个滚动帧做 900 多次 `getBoundingClientRect` 并重渲染整张列表；同时未渲染的页用第 1 页的尺寸占位，真实高度要等渲染完才知道，于是滚动位置会漂、目录跳转要等目标页渲染完才"落定"。实测（926 页 ≈26 MB 扫描书，侧栏 481 px 宽、DPR 2）：

| 指标 | 0.1.3 | 0.1.4 |
|---|---|---|
| 文档里的页框节点 | 926 | 4–5（视口 ±1 屏） |
| 每个滚动帧的 `getBoundingClientRect` | ~940 | 2 |
| 连续滚动的帧耗时 p95 / 最长 | 59 / 103 ms | 34 / 45 ms |
| 目录跳转：目标页出现 | ~700 ms | ~120 ms |
| 目录跳转：滚动停止 | ~1100 ms | ~300 ms |
| 单页渲染耗时 | 100–720 ms | 12–210 ms |
| 全流程主线程长任务累计 | 3100–3700 ms | 520–820 ms |

做法：

- **页面尺寸表**：打开时先并行量出全部页面的真实尺寸（926 页约 0.2 s），再把每页按绝对定位落到累计偏移上。滚动位置、目录跳转、页码跳转、续读因此都基于确定的几何，不再依赖"占位尺寸 → 渲染后改高"。
- **虚拟化**：只挂载视口上下各一屏的页框，滚动时用二分查找算出可见范围，只在范围变化时重渲染；当前页、阅读位置全部由 `scrollTop` 推出，滚动期间不读 DOM。
- **单一渲染泵**：页位图串行渲染、按离当前页的距离排序，滚出窗口的排队项直接丢弃、在途渲染中止，已渲染的位图留在小型 LRU 里，来回滚动不重复光栅化。
- **适应宽度以"出现最多的页宽"为基准**：这本 PDF 的封面是 252×327 pt、正文是 589.68×792 pt，按第 1 页定缩放会把正文撑到侧栏外并让每页多渲染 5 倍像素。
- **当前页取视口顶边所在页**（而非"可见面积最大"）：与跳转落点严格互逆，缩放窗口或封面比正文矮时不会把当前页算成下一页。

## 与其他插件的区别

本插件只增强已有工作区 PDF 的右侧预览，提供内嵌目录与个人阅读书签。论文文献库、AI 伴读、PDF 内容提取与批注工作台解决其他需求；本插件不增加模型工具或会话持久状态。社区目录中的会话书签与文件路径收藏也不等同于 PDF 页内阅读位置。

## 0.1.5 更新说明

- 修一个会让整份 PDF **完全打不开**的缺陷：内容键依赖的 `crypto.subtle` 只在**安全上下文**（https、localhost、file）里存在。用 http 域名访问 dsh（例如 `http://dshu:3080`、局域网 IP）时它是 `undefined`，阅读器在打开阶段就抛 `Cannot read properties of undefined (reading 'digest')`，页面只剩这行错误；同样原因下 `crypto.randomUUID` 也缺失，保存书签会报 `is not a function`。
- 现在缺 `crypto.subtle` 时退到自带的纯 JS SHA-256（`src/sha256.js`），输出与原生**逐字节一致**，所以内容键不变、已有书签与续读数据不需要迁移；实现分片计算并让出主线程，27 MB 文档也不产生长任务（实测最长任务 0 ms，都是短切片）。
- `newId()` 用 `crypto.randomUUID` → `getRandomValues` → `Math.random` 三级降级，书签 id 仍是标准 UUID v4。
- 内容键与 PDF 解析、页面尺寸表并行计算，降级路径不会额外拖慢首屏（代价：http 源上首次打开 27 MB 文档约多 0.8 s，同一次会话内重复打开命中内存缓存；https 源走原生实现无此开销）。
- 25 项 Node 测试通过（新增 2 项：无 `crypto.subtle` 环境算出同一把键、无 `randomUUID` 环境生成合法 id）；16 项浏览器功能回归全过；另在**真实非安全上下文**（`http://` 域名 + Chromium 147）端到端验证：打开、渲染、加书签、滚动存进度、刷新续读全部正常，控制台零错误，算出的键与 `sha256sum` 一致。

## 0.1.4 更新说明

- 渲染重写：页面列表虚拟化、真实尺寸表、串行渲染泵与位图缓存，`getBoundingClientRect` 从每帧 900 余次降到个位数；926 页文档的目录跳转由 ~700 ms 降到 ~120 ms，滚动帧劣化从 103 ms 降到 45 ms。

## 发布流程

1. 修改源码后执行 `npm run build`、`npm test` 和 `node scripts/host-smoke.cjs`；Host 验证需要本机 DSH Desktop。
2. 同步更新 `package.json`、`package-lock.json` 与本文版本说明，打包到 `dist/`，更新带版本号的包、固定名称包和对应 SHA-256 文件。
3. 创建对应 `v版本号` 标签，将提交与标签一起推送；随后在 GitHub 创建正式 Release，上传带版本号的安装包、固定名称 `dsh-pdf-bookmarks.tgz` 及两份 SHA-256 文件，将其设为 latest。先核对标签、包版本和校验值，再发布；已有历史 Release 保留。
4. 使用 npm 官方仓库登录，执行 `npm publish ./dist/dsh-pdf-bookmarks-版本号.tgz --access public --tag latest --registry=https://registry.npmjs.org --ignore-scripts`，按 npm 账户要求完成二次验证。
5. 核对 npm latest、GitHub latest 和 Release 资产校验值一致，再更新本机插件。仅修改源码不会自动升级已安装的旧插件。
